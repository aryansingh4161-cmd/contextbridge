# ContextBridge — Known Limitations (verified 2026-10-31)

Sources are cited in `docs/BLUEPRINT.md` §2. Rows marked *(to test)* are not yet confirmed.

| Reality | Consequence | Design response |
|---|---|---|
| An MCP server only sees what the model sends in tool calls. | The server can't watch or summarize chats. | Model-driven writes guided by instructions, tool descriptions and `checkpoint_status`; transcript ingestion from files; Claude Code hooks. |
| Claude Desktop / claude.ai expose no usage or context telemetry to MCP servers. | No budget monitoring there. | Time/activity-based nudges + manual handoff; UI says "telemetry unavailable". |
| Claude Code status line **does** expose `context_window.used_percentage` and, for Pro/Max/Ultra only, `rate_limits.five_hour/seven_day.used_percentage` + `resets_at`. These may be null/absent early, after `/compact`, or after a reset. | Telemetry is partial and plan-dependent. | Every field optional; absent shown as "unavailable", never 0; readings older than a configurable age flagged stale. |
| An MCP server cannot interrupt the model mid-generation. | No hard "stop and save". | Claude Code `Stop` hook can block a stop (`decision:"block"`) at a turn boundary; guarded by `stop_hook_active`, a per-session state file, and Claude Code's 8-continuation cap. Elsewhere: warnings + manual command. |
| `SessionEnd` hooks can't block and have a **1.5 s default timeout**; `StopFailure` output is ignored. | The emergency path can't rely on the model or a long-running hook. | Detached `ctxb emergency` child process; deterministic, model-free. |
| An MCP server can't push context into a new chat. | Resume needs a trigger. | `resume` prompt, `get_context`, resources, CLAUDE.md snippet, standalone file. **Exception:** Claude Code `SessionStart` hook can inject `additionalContext` (≤10k chars inline). |
| Claude Code caps MCP tool output (warning at 10k tokens, default max 25k). | Large handoffs can't be returned inline. | 8k-token inline cap; larger content written to file, path returned. |
| Each client starts its own server process; Desktop may share one across chats. | Concurrent writers; no safe "active project" global. | SQLite WAL + busy timeout + short `BEGIN IMMEDIATE` transactions; explicit `project` on every tool. |
| Claude upload limits: chat 500 MB/file & 20 files; Projects 30 MB/file, unlimited count but must fit context. `.md` and `.zip` are **not** in the documented type list (TXT, JSON, PDF, … are). | Exports must fit; `.md` may be rejected. | Config-driven profiles; size + token checks; splitting; `.txt` preferred for uploads; ZIP only for local backup. |
| ChatGPT and claude.ai web connectors require **remote HTTPS** MCP; local stdio isn't supported there. | MVP (stdio) can't connect to them. | Standalone context file; HTTP transport is a later phase (localhost + auth). |
| **Verified 2026-10-31 (with the user):** Claude Desktop connects to the server, lists its tools/prompts/resources and runs tools, but does **not** show the server's `instructions` to the model (the model reported seeing only tool descriptions). | Habits aren't taught by the instructions text in Desktop. | The habits travel in the results of `list_projects`, `create_project` and `get_context` (`usage` field), in tool descriptions and `checkpoint_status`; plus the paste-in project-instructions snippet (`ctxb snippet desktop`). |
| Claude Desktop config persisting across claude.ai account switches is expected (local file) but undocumented. *(to test in M7)* | — | Manual test. |
| Claude data-export format **not verified** (no export available on this machine). | The `claude_export` parser accepts the commonly described shape (`conversations.json` list with `chat_messages` items having `sender` + `text`/`content[].text`) and refuses anything else with a clear message. | Verify with a real export (claude.ai → Settings → Privacy → Export data) and adjust; until then treat results as best-effort. |
| The Claude Code transcript format is internal and undocumented (verified on 2.1.316 only). | A Claude Code update could change it. | Tolerant parser: unknown records skipped, file refused if no messages are recognized; re-verify when Claude Code updates. |
| Markdown/text imports guess each item's kind from keywords. | Kinds and topic keys can be wrong. | Marked `kind_guessed`; corrected with `edits` on commit; committed items stay `imported` until confirmed. |
| Instruction-like text in imports is detected by a regex heuristic. | Some injections won't be flagged. | Flags are informative only: imported content is never executed or followed either way, and is always wrapped as data. |
| Token counts are estimated offline (no API key). | Numbers are approximate. | Ranges + confidence; calibrated from `handoff_runs`. |
| Conflict detection is keyed on `topic_key`; semantically conflicting entries under different keys can slip through. | Some conflicts are found only by the model or validator. | Similar-key suggestions; consistency heuristics; documented as heuristic. |
| iCloud "Desktop & Documents" sync marks some files `hidden`; Python 3.14 skips hidden `.pth` files. Syncing a live SQLite DB through iCloud can corrupt it. | Dev venvs on the Desktop break; a DB in iCloud is unsafe. | Dev venv in `.venv.nosync/`; data dir `~/.contextbridge` (not synced); `doctor` warns on iCloud paths (M2). |
| The Live State ↔ knowledge consistency check for free text is a heuristic: it compares the distinguishing words of a superseded decision's title with its replacement's. | Some inconsistencies are missed (synonyms, values only in bodies); rare false positives are possible. | `refs` from state sections to entries are checked exactly; the text check is labelled "heuristic"; the model is asked to pass refs. |
| Timestamps are local time with UTC offset, microsecond precision (fixed in M4; was 1 s, which under-counted unsaved writes). Ordering compares the strings. | Across a DST/timezone change, events within the shifted hour can compare out of order. | Same-offset ordering is exact; affects only advisory counts (`writes_since_checkpoint`, "recent since last handoff"). |
| Handoff ranking is deterministic and heuristic (importance, status, kind, recency, references from Live State/tasks). | Under a small budget, a non-critical entry the user cares about may be shortened to one line or moved to a companion file. | Critical entries are always in the primary file; nothing is dropped from the package; the file lists what was left out; `complete: false` unless nothing was. |
| The completeness score is a share of checks passed, computed from what is stored. | It cannot know about work that was never saved. | Coverage gaps (sessions never checkpointed, writes after the last checkpoint) are stated; the score is labelled informative. |
| Repo details come only from read-only `git` in a directory the user linked (`ctxb link`). | No repo info without git or a link; file contents are never exported. | Paths of changed files + branch + last commit, with "same Mac: read it there" retrieval notes. |
| Secret redaction errs on the side of over-redaction (e.g. `oauth_provider: google` is redacted). Numeric LLM token counts (`max_tokens: 4096`) are exempt. | Some harmless values appear as `[REDACTED:…]`. | Types are reported, values never; adjust wording if needed. |
| Upload profile limits come from Anthropic's help page; actual uploads of generated `.txt` packages to claude.ai have not been tested from this machine. *(to test in M7)* | A profile could be stale. | Values live in config; `preferred_ext` and limits are one edit away. |
| After an id-remapping import, old exported files (and stored handoff snapshots) still show the old tags. | `[D-0012]` in an old file may now be entry 57. | The import returns the id map; preserving ids (the normal empty-DB case) avoids it. |
| Two diverged copies of one project (e.g. used on two Macs) cannot be merged. | Import refuses an existing slug. | Import as a copy (`--as`) and compare; true merge/sync is a later feature. |
| `import_context` (the AI choosing a path) may only read files under `[import] allowed_dirs` (default ~/Desktop, ~/Documents, ~/Downloads), ~/.claude/projects and ContextBridge's exports. | Importing from elsewhere through the AI fails with a clear message. | Add the folder to `allowed_dirs`, or run `ctxb import` yourself (any non-hidden path). |
| The SessionStart hook only knows which project to load if the folder was linked (`ctxb link`). | Unlinked folders get no automatic context. | Link once per project; otherwise ask Claude to `get_context`. |
| Hook output is capped by Claude Code at 10,000 characters. | Very large briefs are cut. | We cap at 9,500 and point to `get_context` for the rest. |
| The budget monitor only works in Claude Code (status line + hooks). Usage limits (5h/7d) only appear for Pro/Max/Ultra, after the first response. | Desktop/web get no automatic budget actions. | `checkpoint_status` nudges by time and unsaved writes everywhere; `get_budget_status` says "unavailable" honestly. |
| The Stop hook can only act at the END of a turn; a single huge turn can still hit a limit mid-way. | Some work in that turn may be unsaved. | Early thresholds (80/85) leave room; PreCompact archives the transcript; SessionEnd/StopFailure write an emergency handoff. |
| Emergency handoffs contain only what was saved; the archived transcript is raw. | The newest unsaved discussion isn't summarised. | The file says so explicitly and points to the archived transcript for the next assistant. |
| `forget` keeps a recovery point (snapshot, or a full archive for a project), so forgotten data is still on disk until `ctxb purge`. | "Forget" is reversible, not erasure. | `ctxb purge` (project or `--entry`) removes it from the DB, snapshots, backups and recovery archives; handoff files already in `exports/` are separate files (purging a project deletes its exports folder; purging one entry does not edit old handoff files). |
| Splitting a single indivisible block (one huge code block or table) larger than the size limit is impossible without breaking it. | That part stays oversized. | Reported as a warning; such blocks are rare in handoffs (bodies are kept verbatim). |
| Claude Desktop / claude.ai chats can't be captured live or word for word (no API gives other programs access). | Desktop chats are saved as structured items while you work, not as transcripts. | Word-for-word import afterwards from the official claude.ai data export (`--type claude_export`, choose chats with `--match`/`--select`). The export format is still to be verified with a real export. |
| Images pasted into a chat can't be stored by ContextBridge; the claude.ai export contains only their names. | A screenshot shown only in chat is lost unless saved. | Save it to a file and `attach_file` / `ctxb attach` it; the export import notes "[attached file: name (file itself not in the export)]". |
| Attachment text search covers text-like files only (txt, md, csv, json, code). PDFs, images and Office files are searchable by name and note. | Words inside a PDF aren't found by search. | Add a descriptive note when attaching; text extraction for PDFs would need a dependency (later). |
| The stored copy of an attachment is the original file; only the search index is redacted. | A secret inside an attached file stays in that file. | Private keys are always refused; the AI can't attach files that contain secrets (only you can, via `ctxb attach`, with a warning); secret-bearing attachments are never copied into upload packages; delete with `ctxb delete <slug> --attachment ID --yes` or `ctxb purge`. |
| Secret detection in attachments is pattern-based: every file is scanned (tolerant decoding), plus text inside Office/iWork ZIPs and Flate-compressed PDF streams. | Secrets in unusual encodings (e.g. images of text, other PDF filters) can be missed. | Containers that can't be inspected are treated as risky for AI-chosen attachments and upload packages (fail closed). |
